FinVault — Full Project Plan

Next.js + MongoDB · Personal accounts, income & expenses, and group expense management · Phase-by-phase build

Phase 0 — Foundation (Next.js + MongoDB + Auth)

#FeatureTest / Acceptance
0.1 Next.js project setup, MongoDB connection (Mongoose, local instance) App boots, /api/health confirms DB connection
0.2 User model + signup / login (JWT or session-based) Can register, log in, protected route rejects requests with no token
0.3 Base layout, protected route wrapper, navigation shell Logged-out user is redirected to login from any protected page

Phase 1 — Individual Accounts

#FeatureTest / Acceptance
1.1 Account model — name, type (bank / cash / wallet), currency, balance, owner Create account via API, appears in DB with correct owner
1.2 Transaction ledger model — the single source of truth for balances Every balance change writes exactly one Transaction row
1.3 Account CRUD API + UI (list, create, edit, delete) Create / edit / delete reflected instantly in UI and DB
1.4 Account detail page — current balance + transaction history Displayed balance always matches sum of that account's transactions

Phase 2 — Individual Income & Expenses

#FeatureTest / Acceptance
2.1 Expense model, tied to an Account, writes a debit Transaction Adding an expense reduces account balance by the exact amount
2.2 Income model, tied to an Account, writes a credit Transaction Adding income increases account balance by the exact amount
2.3 Categories — predefined + custom, applied to expenses / income Entries can be tagged and filtered by category
2.4 Personal dashboard — balance per account, spend-by-category breakdown Dashboard totals match the sum of underlying accounts

Phase 3 — Groups (Structure Only)

#FeatureTest / Acceptance
3.1 Group model + create / rename / delete Group visible to creator and added members only
3.2 GroupMember model — registered users + guests Both member types listed correctly in the group member list
3.3 Add / remove member, roles (admin / member) Non-admin is blocked from remove / rename actions
3.4 Guest invite email Email sent on guest add, invite link works

Phase 4 — Linking Accounts to Groups

#FeatureTest / Acceptance
4.1 GroupMemberAccount — link one or more personal accounts to a group User can attach an account, sees it listed in group settings
4.2 Set a default / primary account per group New group expense defaults to this account as the payer source

Phase 5 — Group Expenses (Money Moves for Real)

#FeatureTest / Acceptance
5.1 GroupExpense model — Equal split Payer's account debited full amount; each member's share computed correctly
5.2 GroupExpense model — Manual split Custom split amounts sum exactly to the total expense
5.3 Real account debit on expense creation, tagged group_expense Single Transaction row created, sourceId points back to the expense
5.4 Edit / delete an expense reverses the linked Transaction Account balance returns to pre-expense state after delete
5.5 Live group balance calculator (GET /:id/balances) "Who owes whom" always matches manual calculation from expense records

Phase 6 — Settlements / Transfers

#FeatureTest / Acceptance
6.1 GroupTransfer model — Pending → Confirm / Reject (two registered users) Transfer stays pending until receiver confirms; balances unaffected until then
6.2 Auto-confirm when a guest is on either side of the transfer Transfer involving a guest settles immediately, no confirm step shown
6.3 Confirmed transfer debits sender's account, credits receiver's account Both accounts' balances update by the exact transfer amount
6.4 Settlement suggestions (minimize number of transfers) Suggested transfers fully clear all outstanding group balances

Phase 7 — Guest Claim Flow

#FeatureTest / Acceptance
7.1 Guest claims profile via matching email on signup GroupMember._id preserved — no duplicate history created
7.2 Global "pending claims" prompt on login New user sees any guest profiles matching their email and can claim them

Phase 8 — Polish & Reporting

#FeatureTest / Acceptance
8.1 Combined dashboard — personal + group net worth Net worth figure matches sum of all account balances
8.2 Currency conversion (e.g. USD/PKR), applied consistently All displayed totals convert correctly, no double-conversion
8.3 Notifications — email + in-app for key events Expense added, settlement requested/confirmed all trigger notifications
8.4 Edge-case hardening + test pass across all phases No orphaned transactions, no balance drift after stress-testing edits/deletes
